# 14. 개발 우선순위

기준: 2026-10-03. 최종 목표는 가벼운 온라인 2D 픽셀 MMORPG 제작 엔진이다. [36개 작은 작업](22-2d-mmorpg-roadmap.md)의 완료 조건으로 진행하며 2D 제작·플레이·서버·UI·배포를 우선한다. 라이브러리 통과를 게임 제작·출시의 통합 완료로 확대하지 않는다.

| 순위 | 필요한 항목 | 근거 | 완료 조건 |
|---|---|---|---|
| P0 | 인증·전송·저장·원장 실패와 복구 | 공개 서버는 로컬 JSON·테스트 계정·평문 전송의 한계를 가진다 | 암호화 전송·비밀번호 저장 검증·중단 복구·원자적 거래·강제 오류/재시작에서 데이터 보존 |

| P3 | 3D 제작·선택·기즈모·메시 임포트 확장 | 기존 지원을 보존하며 2D 목표 이후로 순서를 변경 | 실제 3D 제작 요구가 다시 생길 때 XYZ 선택/TRS·glTF 노드/재질 검토 |
| P3 | 3D 물리 확장·orbit 고도화 | 구현된 범위는 유지; 새 임의 메시/강체·카메라 확장은 2D 제작을 먼저 완료 | 실제 수요와 호환/렌더/입력 시나리오에 따라 범위 결정 |
| P1 | 게임 UI 제작과 런타임 연결 | 기존 Message/안내의 화면 공간 한글 출력을 Play/MyGame에 연결. 저장한 .ui 임포트·GameUi·Lua 값/게이지/활성 상태를 로컬 앱에 연결. 문서 작성/Undo·저장/재열기·공유 렌더 미리보기도 연결. 로컬 버튼/포커스·모달 입력 차단은 연결. IME/패드 UI·온라인 연결은 미완료 | 제작·저장·실행·실제 HP/가방/퀘스트 값·입력·한글·해상도 변경까지 연결된 사용자 시나리오 |
| P1 | 온라인 2D 맵 전환·게임 규칙·표현 | 동일 정적 2D/XYZ 장면의 기본 온라인은 연결; 2D 맵·포털·게임 규칙·UI는 미연결 | D14→D23: 두 계정의 맵 이동·권위 보상/전투·NPC·HUD·채팅/거래·실제 입력과 재접속 검증 |
| P1 | 게임 내보내기 | 에디터 Release와 완성 게임 배포는 다른 작업이다 | 선택 프로젝트의 실행 파일·에셋·라이선스·설정·새 PC 실행 검증 |
| P1 | Lua 제작 오류 설명·보완 | 콜백 오류 격리·가이드는 연결됐지만 자동 완성·중단점은 없다 | 사용자 요구에 따른 API 탐색·오류 위치·지원 범위 검증; 기능을 묶어 VM 재작성하지 않음 |
| P2 | 에셋 재임포트·파일 감시·안전한 이동 | 현재 가져오기/갱신은 수동이며 GUID 이름 변경 워크플로가 없다 | 편집·런타임 참조 보존·실패 롤백·중복 GUID/삭제 경계 검증 |
| P2 | 별도 Play 프로세스 | 현재 창만 분리되어 게임 오류가 에디터를 종료할 수 있다 | 저장되지 않은 실행 스냅샷·프로세스 수명·pause/stop·오류 격리 검증 |
| P2 | render/scene 의존성 정리 | PRIVATE include를 통한 실제 타입 결합이 남아 있다 | 공용 렌더 입력 계약과 타깃 의존성 정리, 깊이·층·피벗 캡처 회귀 |
| P2 | 측정에 근거한 성능·크기 | 세계 최소 크기·최고 효율은 측정 없이 보장할 수 없다 | 동일 Release 장면에서 CPU/GPU·할당·배치·파일 크기 전후 기록 |
| P3 | 다른 플랫폼·렌더 백엔드·운영 확장 | 현재 Windows/DX11 요구가 명확하다 | 실제 출시 타깃·부하·장치가 확정되면 범위 결정 |

프로젝트 창, 3개 작업대, 요소 추가, 필드 설명, 별도 게임 창, 에셋 우클릭 관리, 직접 Lua 바인딩, MCP 참조·임포트, 버전/Release 경로를 구현했다. 검증 결과와 확인하지 못한 환경은 [변경 기록](16-foundation-worklog.md)에 남긴다.

3D 공용 등록·정적 메시·빌보드·저장 카메라·요소 추가/Undo와 공통 상자/경사 물리·XYZ Lua·로컬 포털을 연결했다. 동일 장면의 인증 온라인 클라이언트·2D/XYZ 복제/영속을 제공한다. 외부 프로젝트 제작 루트는 개발 MCP에서 명시적으로 지정하며 루트 탈출 검사를 유지한다. NPC·온라인 맵 전환·게임 UI·채팅·게임 내보내기·관심 영역은 완료되지 않았다. P0는 공개 운영 차단 조건이다. D02~D05의 기본 소스 연결 이후 P1은 2D 제작/카메라/입력→맵→규칙/UI→운영/배포 순서다.

표준 위향 GLB 앞면과 지정 에셋의 명확한 오류 종료는 0.2.3에서 수정했다. 여섯 축 앞/뒤 픽셀·두 공식 앱의 동일 원본 임포트·누락/손상 메시 및 지정 PNG의 오류 종료 회귀를 유지한다. 0.2.2의 반대 컬링에 맞춘 사용자 모델은 외부에서 표준 앞면으로 다시 내보내고 실제 지형·건물·다리를 재검수한다. 원본/GUID를 자동 변경하지 않는다. 현재 XYZ 물리/게임 카메라의 범위는 21번 계약을 따른다. P2 조명/접지 그림자는 실제 장면·아트 검수와 비용 측정 이후 범위를 정한다.

도트 제작·내장 리깅·구 데모·중복 씬 작업대는 요청에 따라 제거했다. 외부 제작 도구와 기존 애니메이션 에셋이 같은 필요를 충족한다. Lua VM·ImGui·실제 디코더 자체 구현은 코드 크기·수명·오류 경계의 비용을 입증하기 전에는 추가하지 않는다.

0.3.0의 지원 범위와 근거는 [21](21-3d-play-and-online.md)에 있다. 정적 상자와 +Z 경사, 360° orbit, 동일 장면 루프백 서버를 먼저 구현했다. 임의 회전/메시 물리, 실제 장치 입력 검수, 카메라 상대 8방향 에셋 매핑과 공개 온라인 운영은 별도 완료 조건으로 유지한다.

2D 모션은 공통 시간 비율 보정·반전 발 피벗·미리보기 재생/일시정지와 완료 전환을 연결했다. D08c2의 재생 도중 연속 로컬/온라인 픽셀·일시정지/재개와 이동/스냅샷도 검증했으며 행동 데이터의 저장/참조 검증(D08d1)을 연결했으며 저장 상태의 앱 바인딩(D08d2a)을 연결했다. 다음은 행동 문서 작성/Undo·재로드(D08d2b)→입력·중단/완료(D08d3)다. 세부 범위는 [26](26-2d-animation.md)과 [작업 목록](22-2d-mmorpg-roadmap.md)을 따른다.

최신 피드백은 작업 번호보다 우선한다. 화면 공간 UI의 첫 단위인 실제 게임 창 Message·한글 표시를 연결했다. 저장한 UiDocument의 임포트·게임 상태 표시는 연결했다([27](27-game-ui.md)). UI 문서 작성/Undo·저장과 미리보기를 연결했다. 로컬 버튼/포커스·모달 차단을 연결했다. 다음은 IME/패드 UI·실제 장치 검수와 행동 작성/입력·중단, 프리팹 생성/질의, 프로젝트 상태의 맵/저장 수명, 권위 규칙 순으로 진행한다. [피드백 우선 실행 순서](22-2d-mmorpg-roadmap.md)에 근거와 각각의 완료 조건을 기록한다. 게임측 피해/가방/퀘스트 수치를 엔진에 다시 구현하지 않는다.
