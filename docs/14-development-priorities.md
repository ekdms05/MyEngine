# 14. 개선·개발 우선순위

기준일: **2026-10-01**. 코드 호출 경로와 실제 검증을 기준으로 한다. 수정 내역·측정·삭제 이유는 [작업 기록](16-foundation-worklog.md), 실제 앱 조합은 [구조 문서](13-architecture-and-features.md)에 있다. 로컬 개발 기반과 외부 서비스 완료를 구분한다.

## 판단 기준

| 우선순위 | 의미 |
|---|---|
| P0 | 데이터 보존·경제·접속 신뢰 경계. 실제 운영 데이터·외부 접속 전에 완료 |
| P1 | 플레이·편집의 정확성과 기존 모듈의 제품 연결 |
| P2 | 콘텐츠 생산·계층·측정에 따른 성능·배포 개선 |
| P3 | 실제 요구·부하를 근거로 하는 플랫폼·운영 규모 확장 |

파일 길이·TODO 개수 대신 영향도, 재현 경로, 선행 조건으로 순서를 정한다.

## 유지·삭제·품질 기준

소유권·상태·실패를 이름과 호출 경로로 이해할 수 있어야 한다. 공통 규칙은 [AGENTS.md](../AGENTS.md)를 따른다. 사용처 없는 무동작 Pin/Unpin과 앱의 미사용 setter는 제거했다. 사용자가 만든 에셋과 실제 호출자·테스트가 있는 모듈은 보존했다. 파일 크기만으로 모듈을 잘게 나누거나 일괄 포맷하지 않는다.

완료 조건은 관련 빌드·최소 회귀·실제 앱 경로·필요한 화면/장치/실패 검사다. 성능은 동일 Release 조건의 전후 결과로 판단하며, 테스트 개수로 서비스·콘텐츠 완성을 선언하지 않는다. 변경할 때 [13](13-architecture-and-features.md)의 상태와 [16](16-foundation-worklog.md)의 근거를 함께 갱신한다.
