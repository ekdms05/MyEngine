## 검증

### 3D 제작 피드백 반영 — 2026-10-02

공식 앱의 최소 BillboardRenderer·MeshRenderer 씬이 `unsupported component`로 거부되는 문제를 재현했다. 수정 전 같은 기준 프로젝트에서 SpriteRenderer는 두 앱 exit 0, 나머지는 exit 1이었다. 반영 범위는 공통 로딩·표시·카메라·제작 파일 경계다. 게임 사용자의 원문 피드백·답변·프로젝트·캡처는 해당 로컬 폴더에서 관리하며 public 저장소에 포함하지 않는다.

이 변경의 새 회귀 3개와 기존 워크플로 확장을 포함한 Debug·Release CTest는 각 544/544다. 기존 서버/로컬 플레이어 검증도 통과했다. 실제 두 앱에서 Full/YAxis/None의 저장 카메라 출력은 같은 960×540 픽셀이었고 잘못된 near 값은 두 앱 exit 1로 거부했다. MCP build·smoke, 패키지/공개 CI 결과는 배포 검증 후 기록한다. 키 입력 수동 플레이·별도 PC·인증된 온라인·3D 물리와 목표 아트 품질 승인은 이 캡처의 증거가 아니다.

MCP build·smoke 19개 검사와 외부 제작 루트의 실제 에디터 GLB 임포트·조회·덮어쓰기/탈출 거부를 확인했다. 두 공식 앱에서 빌보드 `.anim`의 시작/후속 캡처가 달라 모션 진행을 확인했다. 원근 깊이 캡처에서는 뒤 메시 앞의 불투명 코어 1,659px, 앞 메시가 가리는 캐릭터 7,012px, 투명 빈 영역으로 보이는 메시 1,642px를 확인했다. 기존 아트의 부분 알파 5,826px는 블렌딩 영향이 남으며 하드 알파 픽셀 에셋 승인은 아니다. 실제 목표 에셋 검수를 대체하지 않는다.

컴파일에는 기존 경고와 Lua의 C ABI 예외 해제를 위해 /EHc를 /EHc-로 덮어쓰는 D9025 경고가 남는다. 경고 없는 빌드나 MSVC 외 플랫폼 검증 완료로 표시하지 않는다. 파일 선택창·휴지통의 실제 사용자 조작, 다양한 DPI/언어 폰트, 실제 키보드 플레이·오디오 청취·별도 PC는 아직 수동 확인 범위다. 게임 창은 같은 프로세스이며 완성된 MMORPG·온라인 클라이언트·게임 내 UI 제작 기능으로 설명하지 않는다.

패키징은 기존 파일을 지우지 않고 새 출력 폴더에서 수행한다. 버전·소스 커밋·파일별 SHA-256은 release-manifest.json에, ZIP 해시는 sidecar에 기록한다. 개인 설치 설정·상세 로그·구 문서 원본·정리한 빌드 경로는 공개 자료와 분리하여 로컬에 보관한다.

나눔스퀘어라운드의 배포 근거는 [네이버 공식 글꼴 모음](https://hangeul.naver.com/font)과 [OFL 1.1 전문](https://help.naver.com/service/30016/contents/18088?lang=ko&osType=PC)이다. 2026-10-02 확인한 Regular TTF는 1,063,276 bytes이며 SHA-256은 `52862fdf05b55ba886ca21998222d9598ef84c975e68046b9a8d8f1af09228a0`이다. 폰트 내부 데이터를 변경하지 않았다.

폰트 교체 후 Debug·Release 빌드와 CTest 각각 541/541, MCP build·smoke를 확인했다. 에디터 구현에 등장하는 한글 515종과 현대 한글 11,172자의 지원을 확인하고 실제 Release 화면 및 ZIP에서 꺼낸 에디터의 메뉴·탭·요소 추가 창을 캡처했다. 로컬 검토 패키지의 76개 파일·폰트/OFL/내장 보완 폰트 고지·ZIP 해시가 원본과 일치했다. 다양한 DPI·별도 PC·게임 프로젝트의 런타임 폰트 교체는 이 검증에 포함하지 않는다.

## 0.2.2 배포 검증

정적 충돌은 기존 벡터 저장과 선형 탐색을 사용한다. 측정 없이 캐시/공간 트리/스레드를 추가하지 않았다. 새 외부 런타임 의존성이나 내장 픽셀 제작 기능은 추가하지 않았다. 변경 책임의 이유로 순수 물리·ECS 연결·온라인 장면 로드만 분리하고 앱/게임 역참조를 막았다. 개발/게임 제작/릴리즈 스킬의 실제 명령과 범위를 함께 갱신했다. 사용자 원본 피드백·에셋·GUID를 보존하고 상세 항목별 답변과 로그/해시/프레임은 게임 프로젝트의 로컬 피드백 폴더에 둔다.

### 서버 실행 주기 회귀 수정

실행 파일의 접속 검사를 늘리자 Windows의 상대 `sleep_for` 대기 오차가 매 틱 누적돼 60틱에 약 1.86초가 걸렸다. 60 Hz 클라이언트의 미확인 입력이 240개 상한까지 쌓여 종료됐다. 서버 루프에서 `steady_clock`의 절대 기한을 누적하고 `sleep_until`로 대기하도록 수정했다. 별도 타이머 라이브러리나 입력 큐 확대 없이 실제 주기 원인을 해결한다. 기존 foundation 검사에 120틱/2.8초 상한을 추가했고 Release 실행은 2.048초로 통과했다. 0.8초는 초기화·스케줄링 여유이며 처리량 벤치마크가 아니다.

### D02 값 계산 경계와 로컬 오류 전달 · 2026-10-03

온라인 2D 목표에서 로컬/서버/예측이 서로 다른 이동 코드를 사용하면 벽·층·속도 결과가 달라진다. 실제 PhysicsWorld2D의 이동 루프와 ObjectSystem/PlayMode/MyGame의 모든 호출자를 추적했다. 기존 Shape2D·층/레이어·상자/원 MTV·타일 질의 계약을 `Motion2D` 값 경계로 옮기고, core만 PUBLIC 링크하는 `mye_physics2d` 타깃으로 분리했다. 성공 경로의 공통 계산은 동적 할당 없이 입력 값을 읽고 결과 값만 반환한다. 월드 어댑터가 엔티티 핸들을 불투명 ID로 변환하므로 순수 계산 헤더에 ECS·에셋·렌더를 포함하지 않는다. 새 물리 라이브러리·팩토리·중복 이동 규칙은 추가하지 않았다.

`PhysicsWorld2D::Step`은 기존 void 대신 Expected를 반환한다. 모든 본체의 계산·원점 복원·범위/공간 해시 검증이 성공한 뒤 Local/WorldTransform·lastMove/hitWall을 반영하고 트리거 diff를 발행한다. 뒤의 본체가 실패했는데 앞의 위치만 변경되는 부분 적용을 막기 위함이다. ObjectSystem이 이 오류를 반환하며 기존 MyGame 실패 처리와 PlayMode의 오류 경계를 재사용한다. 이 보장은 물리 위치/결과/트리거 이력에 대한 것이며, 앞선 Lua 실행·조작 속도 설정·입력 소비를 되돌리는 전체 틱 트랜잭션은 아니다. root LocalTransform을 명시적으로 요구하고 부모가 있는 이동체는 거부한다. 부모 월드 역변환을 조용히 잘못 적용하는 기존 가정을 유지하지 않는다.

유한한 중심·AABB 경계·양수 크기·유효 형상·층 0..7·속도·dt (0,1]·반복 1..16과 타일의 보정 결과를 공통 경계에서 검사한다. 서브스텝 수는 정수 변환 전에 상한을 적용한다. 큰 유한 변위의 길이/크기 비율이 넘쳤는데 float→int 변환부터 하던 순서를 피한다. 최종 변위/원점과 법선 투영이 표현 범위를 넘으면 오류로 반환한다. 저장된 skin·snapToGround는 기존 호환 때문에 보존하지만 아직 계산에서 사용하지 않는 데이터임을 문서에 명시했다.

공간 해시는 AABB의 float 셀 좌표를 곧바로 int32로 바꾸고 두 축의 모든 셀을 순회했다. NaN/역전 범위는 삽입/콜백 전에 거부하도록 Insert/QueryAABB도 Expected로 바꿨다. 셀 좌표는 double로 계산한 뒤 정수 범위를 검사하며 반복 인덱스는 int64로 사용한다. 한 항목/쿼리의 셀 등록은 4,096개로 제한하고 큰 영역·정수 범위 밖은 기존 항목 목록과 직접 겹침 검사한다. 큰 맵 벽을 삭제하거나 크기 제한으로 거부하지 않는다. 잘못된 항목 삽입은 ItemCount를 바꾸지 않고, 셀 크기를 바꾸면 이전 인덱스를 비운다. 큰 항목이 많을 때 최악 O(n²)인 실제 한계와 측정된 병목이 생기면 트리로 바꿀 조건을 주석/가이드에 남겼다. 성능 향상 수치를 주장하지 않는다.

유한한 큰 형상을 기존 원 계산에 넣으면 제곱 거리와 제곱 반지름이 모두 무한대가 되어 겹침을 놓치거나 NaN MTV를 반환했다. 기존 형상 회귀에 큰 입력을 추가해 **555/557**, 원-원/원-상자 두 시나리오 실패를 실제 재현했다. 상자 크기 합과 원-원 거리/반지름 합은 double 중간값, 원-상자 거리는 hypot으로 계산한다. 저장 타입·좌표 계약은 바꾸지 않는다. float로 표현할 수 없는 보정은 상위 이동 오류 경계가 거부한다. 이 경계 검사는 초대형 월드의 렌더/좌표 정밀도를 보증하지 않는다.

정의와 전체 호출자 검색에서 IPhysicsWorld를 통한 소비와 RegisterPhysicsSystem 호출이 없었다. 단일 구현용 가상 인터페이스와 사용되지 않는 PhysicsSystem 파일 두 개를 제거했다. void SystemScheduler 콜백에 새 물리 오류 프레임워크를 얹는 대신, 이미 Expected를 쓰는 실제 ObjectSystem 경로를 유지한다. 사용되지 않는 TriggerPairKey와 Collision.cpp의 HalfExtents도 제거했다. 별도 물리 구현이나 실제 스케줄러 소비가 생기면 그 수명/실패 계약으로 재검토한다. 사용자 프로젝트·씬/에셋/GUID·기존 공개 배포본은 수정하지 않았다.

기존 검사 프레임워크에 다섯 시나리오를 추가했다: 상자/원과 오프셋·층/레이어의 값 계산/월드 결과 일치, 두 번째 본체 실패 시 위치/결과/트리거 이력 보존, 잘못된 입력/타일 반환 거부, 큰/범위 밖 공간 해시와 쿼리의 정확한 후보·실패 시 보존, ObjectSystem의 물리 오류 전달. 기존 형상 검사에는 큰 수치 경계를 확장했다. 검사 작성 중 없는 World::Get와 void 이벤트 콜백의 컴파일 계약 오류를 기존 TryGet·bool 반환으로 수정했다. 실행 검증과 컴파일 실패를 엔진 런타임 결함으로 혼동하지 않는다.

foundation에는 복사한 기본 프로젝트의 Lua on_init이 NaN 속도를 쓰는 실제 MyGame 검사를 추가했다. 초기 씬 검증 이후의 물리 실패가 exit 1로 전달되고 원본 씬 해시가 유지되는지 검사한다. 사용자의 실제 프로젝트나 저장 데이터는 쓰지 않는다. 기존 로컬 맵/스폰/Lua·960×540 캡처·서버 저장/재시작/손상 거부도 유지한다. MCP는 기존 scene 참조를 최신 계산/오류 계약으로 갱신하고 한 스모크로 반환 문서를 검사한다. 도구 수/프로토콜은 늘리지 않았다. 로컬 개발·게임 제작·릴리즈 세 스킬도 소스 변경과 배포 지원을 구분하도록 갱신했다.

물리 실패 검사 뒤에는 정상 씬 JSON을 복원하고 기존 잘못된 프로젝트 버전 검사를 수행한다. NaN 씬의 물리 오류가 버전 거부 검사까지 대신 실패하게 만들지 않도록 검사 조건을 독립시킨다. 최종 기존 build/dev의 Debug/Release 빌드와 CTest는 순차 실행해 각각 **557/557** 통과했다. Release foundation도 통과했고 120 서버 틱은 **2.061초**였다. 실제 MyGame의 NaN 이동 거부/exit 1·씬 보존, 기존 맵/스폰/Lua·캡처·저장 검사를 확인했다. MCP build와 smoke **22개**가 통과했고 diff --check도 통과했다. 이번 변경에서 새 C++ C계열 경고는 없었으며 기존 MSVC D9025 예외 옵션 재정의 경고는 유지했다. 네이티브 UI 오류 표시·키/마우스/패드 입력·새 2D 온라인 앱·성능 부하 검사는 수행하지 않았다.

이번 단위는 D02의 값 경계/로컬 연결이다. 최대 16개 이산 substep의 얇은 벽 통과 한계가 남아 있으므로 다음 단위는 연속 상자/원 캐스트·초기 겹침·복수 접촉이다. 이어 D03/D04에서 작성 장면과 인증 입력을 서버/예측에 연결하고 D05의 두 공식 2D 클라이언트를 검증한다. 새로운 온라인 지원·공개 운영·실제 장치 입력 완료로 표시하지 않는다. 현재 main의 개발 변경이며 기존 0.3.0 태그/설치본은 그대로 둔다. 실패/성공/앱 로그는 로컬 `build/2d-foundation/d02-*`에 보존한다.
