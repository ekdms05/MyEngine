# 온라인 2D 픽셀 MMORPG 제작 목표와 작업 목록

MyEngine의 존재 이유는 **온라인 2D 픽셀 MMORPG를 간단하게 제작하고 검증·배포하는 것**이다. 엔진을 직접 만드는 목적은 설계와 실행 경로를 이해하고 필요한 기능을 작은 코드로 연결하기 위함이다. 2D 제작과 실제 게임 실행을 우선한다. 구현된 3D 기능과 사용자 프로젝트는 유지하지만 새 3D 확장은 뒤로 둔다.

최종 완료는 두 사용자가 계정으로 접속해 같은 2D 세계에서 이동·전투·보상·거래·대화·맵 이동을 수행하고, 재접속과 서버 재시작 후에도 데이터가 보존되며, 제작한 게임을 독립 배포할 수 있는 상태다. 라이브러리 테스트나 한 장면의 표시만으로 완료를 선언하지 않는다.

## 구현 원칙

- 씬·GUID/VFS·Lua·고정 틱·Undo·기존 위젯·게임 규칙을 재사용한다. 별도 게임 실행기와 중복 물리는 만들지 않는다.
- 캐릭터는 XY로 이동한다. +Y up, PPU 48, 960×540, 발 피벗·층·깊이·cutout 계약을 유지한다. 시각 높이는 권위 이동 좌표와 구분한다.
- 서버가 이동·충돌·피해·보상·인벤토리·거래를 결정한다. 클라이언트 표현이나 Lua 호출을 권위로 신뢰하지 않는다.
- 기능마다 작성→저장→재로드→Play→MyGame→필요한 서버 경로를 확인한다. 공통 계산과 앱 연결은 별개 완료 항목이다.
- 픽셀 제작·모델링·리깅은 외부 도구와 제작 스킬에서 수행한다. 엔진에는 임포트·모션 연결·재생을 둔다.
- 운영 보호·파일 검증·오류 전달·데이터 보존은 간소화하지 않는다. 최적화는 동일 Release 장면에서 측정한 뒤 적용한다.
- 외부 코드를 실제 포함한 부분의 저작권·라이선스 고지는 보존한다. 제품 설명은 MyEngine의 기능과 사용 흐름으로 작성한다.

## 현재 경로와 첫 작업

현재 로컬 2D는 `ObjectSystem → PhysicsWorld2D → MoveAndSlide2D → Transform`을 사용한다. 값 계산은 core만 링크하는 mye_physics2d로 분리했다. 인증 2D의 서버/예측은 StepMotion2D로 같은 계산을 소비하며, legacy XY는 별도 적분이다. `MyGame --connect`와 프로젝트를 지정한 `MyServer`는 공용 로더의 활성 캐릭터에 따라 인증 2D/XYZ를 선택한다. 두 공식 앱의 2D 이동·원격 픽셀/삭제·벽 충돌/ack·저장/재시작 재접속을 검증했다. 동일 정적 장면의 기본 연결이며 완성 MMORPG 제작이나 출시 완료는 아니다.

벽의 접선 이동 중복을 수정하고 로컬 값 계산을 분리했다. 연속 상자/원 캐스트와 실제 MyGame의 Lua 이동을 검증했으며, 로더·인증 2D 권위/예측·저장 admission/재접속의 라이브러리 경계를 연결했다. 작성 장면을 두 공식 앱에 연결하고 입력 재생을 통해 실제 이동/충돌과 스프라이트 픽셀을 확인했다. 다음은 저장 카메라와 입력/모션을 제작 흐름에 연결하는 것이다. 전투·UI보다 먼저 이 경계를 고정해야 이후 기능이 서로 다른 월드 규칙에 의존하지 않는다.

## 우선순위와 진행 규칙

D02는 다음 단위로 나눠 진행했다. **값 계산/로컬 연결**은 ECS·렌더 의존성 분리, 물리 실패 시 위치/결과/트리거 이력 보존과 앱 오류 전달을 검증했다. **연속 충돌**은 빠른 상자/원과 얇은 벽·모서리·초기 겹침·복수 접촉을 검사했고, 실제 MyGame의 Lua 이동·4개 고정 틱 종료/캡처를 확인했다. **권위/예측 연결**은 D03의 스폰과 D04의 인증 입력/ack로 같은 계산을 소비하는 UDP 라이브러리를 검증했다. D05에서 두 공식 앱의 입력 재생·벽 접촉/ack·원격 픽셀/삭제·저장 재시작을 검증했다. 직접 장치 입력은 D07에 남았다. 앞 단위의 테스트를 뒤 단위의 완료 증거로 사용하지 않는다.

D01~D06의 완료 범위는 main 소스의 기본 연결이다. [2D 카메라](24-2d-camera.md)는 기존 render::Camera2D 계산·직렬화·고정 틱을 재사용했고 Play/MyGame/인증 2D에 연결했다. 이름/부모 추종과 현재 시야 상태는 구분하며 런타임 흔들림은 저장하지 않는다. 다음 D07~D14를 온라인 2D 제작 흐름에 연결하고, 전투/콘텐츠와 UI를 한 플레이 행동씩 결합한다. 계정·영속·거래 보호는 해당 기능을 붙일 때 함께 검증한다. D29/D30의 공개 운영 차단 조건은 규모 확장이나 배포 편의보다 앞선다.

D08은 다음 단위로 나눠 순서대로 진행한다. D07의 실제 장치 검수는 별도 조건으로 유지한다.

|---|---|---|

각 작업은 수정할 정의와 모든 호출자를 확인하고 최소 회귀를 남긴 뒤 상태를 갱신한다. 진행 기록에는 사용자 요구·실제 경로·재현·선택 이유·검증·남은 한계를 남긴다. 큰 항목을 한 번에 재작성하거나 기존 테스트가 있는 모듈을 새로 만들지 않는다. 라이브러리 계산만 완료된 항목은 앱 통합을 끝낸 것으로 바꾸지 않는다.

추가 플랫폼·VR/XR·일반 3D 편집/강체 확장·내장 픽셀 제작기는 현재 2D MMORPG 완료 조건에 포함하지 않는다. 필요해지는 실제 게임/배포 요구가 생기면 별도 검토한다. 기존 3D 기능 삭제는 저장 데이터·프로젝트 호환 비용 때문에 수행하지 않는다.

현재 완료 상태와 검증은 [우선순위](14-development-priorities.md), [구조](13-architecture-and-features.md), [작업 기록](16-foundation-worklog.md)을 따른다. 이 문서는 이미 배포된 버전에 없는 기능을 제공한다고 약속하지 않는다.
