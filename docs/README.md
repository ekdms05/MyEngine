## 문서의 역할

`00`~`08`은 시스템별 **설계와 목표 계약**이다. 구현 여부는 소스와 현재 분석 문서에서 확인한다. 예를 들어 초기 설계의 EnTT 선택과 실제 자체 sparse-set ECS는 다르다.

`10`은 단계별 진행 기록을 함께 보관한다. 앞부분의 기능 표와 뒤쪽의 구현 기록은 작성 시점이 다르므로, 앞부분만 보고 네트워크나 게임 앱이 없다고 판단하면 안 된다. `12`는 2026-08-24의 구조 분석이다. 현재 앱 배선과 테스트 수는 `13`을 기준으로 읽는다. 기존 문서는 설계·진행 이력으로 보존한다.

## 갱신 원칙

기능을 추가하거나 앱에 연결하면 `13`의 상태와 `14`의 완료 조건을 함께 갱신한다. 설계를 바꾸면 관련 시스템 문서도 수정한다. 기능 상태에는 소스 위치와 실제 검증 방법을 남기며, 테스트 개수만으로 제품 완성을 선언하지 않는다.
