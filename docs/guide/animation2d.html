2D 캐릭터 모션

캐릭터의 대기·걷기 모션을 .anim 에셋으로 연결한다. main 소스는 로컬 Play·MyGame과 인증 온라인 MyGame에 같은 2D 모션 선택을 사용한다. 바라보는 8방향 값과 방향별 그림 재생은 서로 다른 기능이다. 현재 파일은 단일 클립이며 방향별 클립 저장·편집은 다음 작업이다. 배포된 0.3.0의 지원 범위로 확대하지 않는다.

연결 방법

  1. 외부 도구에서 만든 PNG를 가져오고 애니메이션 패널에서 시트·프레임·시간·발 피벗을 지정한다.
  2. 프로젝트 안에 .anim을 저장한다. SpriteAnimator.animation과 CharacterController2D.idleAnimation·walkAnimation에 에셋을 연결한다.
  3. 씬을 저장하고 Play한다. 정지하면 대기, 실제 이동량이 한 틱에 0.000001 월드 단위보다 크면 걷기를 요청한다. 속도가 낮아도 같은 기준을 사용한다.
  4. 비반복 클립의 후속 모션을 지정하면 완료 뒤 다음 고정 틱에서 그 모션을 재생한다. 같은 이동 상태는 매 틱 시작 클립을 다시 요청하지 않는다. 대기·걷기에 서로 다른 에셋을 연결하면 걷기→정지→걷기는 새로운 요청이므로 처음부터 시작한다.

그림 제작·리깅은 외부 도구에서 수행한다. 엔진의 패널은 가져온 에셋의 연결·시간·이벤트 편집을 담당한다. .meta GUID·기존 에셋 경로와 씬 Undo를 재사용한다.

방향과 이벤트

이동 입력은 방향을, 실제 충돌 후 이동량은 대기·걷기를 결정한다. 벽에 막혀도 벽 쪽을 바라볼 수 있고 입력을 놓으면 마지막 방향을 유지한다. 인증 온라인은 서버/예측의 facingRadians를 같은 8방향으로 변환한다. 로컬은 검증된 이동 입력을 사용한다. 방향 인덱스는 down=0, down_left=1, left=2, up_left=3, up=4, up_right=5, right=6, down_right=7이다. +Y up·발 피벗·48 PPU 계약은 유지한다.

로컬 Lua의 entity:facing_index()·facing_vector()는 현재 방향을 읽는다. face_move(Vec2)는 직접 방향을 지정한다. 활성 캐릭터 조작은 비영 이동 입력이 있는 틱의 후반에 방향을 갱신하므로 on_update는 이전 완료 틱의 결과를 읽는다.

첫 프레임과 이후 진입 프레임의 마커는 고정 틱에서 on_event("animation", payload)로 전달한다. 에셋 바인딩·정지/일시정지 화면의 표시는 커서·상태 전이·트리거·첫 이벤트를 소비하지 않는다. 반복 렌더로 이벤트가 사라지거나 재발행되면 결함이다. 인증 온라인 클라이언트에는 로컬 Lua가 실행되지 않으며 표현 이벤트를 권위 피해·보상으로 사용하지 않는다.

현재 검증과 다음 작업

저장/재로드한 Play·독립 실행 월드의 8방향 값/정지 유지, 공통 요청의 후속 모션·느린 이동·벽 방향, 렌더 샘플의 트리거/첫 이벤트 보존을 기존 테스트에 남겼다. 실제 MyGame의 9틱 입력 재생과 로컬 Lua 이벤트·에디터 Play 캡처도 확인했다. 온라인 회귀는 두 계정의 이동/ack·원격 스프라이트/퇴장·저장/재시작·Lua 격리를 확인한다. 온라인 후속 클립의 전체 픽셀 시퀀스나 직접 장치 입력을 이 검사로 인증하지 않는다.

다음은 방향별 클립의 작성·검증·저장/Undo→재로드/앱 바인딩→방향 변경 시 진행률/발 위치·실제 픽셀 시퀀스→공격·피격·사망 전환 순서다. 메모리의 DirectionalAnimSet·상태 머신만으로 제작 가능한 기능이라고 표시하지 않는다. 작업 목록, Lua API, 컴포넌트, 근거 기록을 함께 확인한다.
