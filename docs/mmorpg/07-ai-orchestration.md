# 07. 제작 도구 연동과 검수

현재 MyEngine의 작업 도구 연동은 [MCP 개발 도구](../08-mcp.md)와 별도로 설치·설정한 [스킬·에이전트 구성](../15-skills-and-agents.md)이다. 엔진에 IAiProvider·AiService·모델 라우터·생성 게이트웨이·생성 패널이 구현되어 있다고 설명하지 않는다.

## 현재 사용할 수 있는 경로

| 작업 | 기존 기능 | 확인 방법 |
|---|---|---|
| 코드 빌드·검증 | engine_build·engine_test 또는 CMake·CTest | 컴파일/테스트 결과와 실제 앱 연결 구분 |
| 실행·화면 확인 | engine_run·engine_capture_frame | 프레임 제한·DX11 캡처·시나리오 결과 |
| 진단 | engine_logs·project_status | 원문 로그·현재 빌드 구성·실제 실행 상태 |
| 픽셀 이미지 제작 | dot_write_sprite·dot_from_photo, 외부 픽셀 제작 스킬 | PNG·투명도·크기·팔레트·시트 규격 검수 |
| 엔진 반영 | 기존 GUID/.meta/VFS·임포터·AssetManager | 임포트 결과·프레임·피벗·소비 앱 확인 |

MCP 등록·스킬 설치·현재 세션에서의 실제 도구 연결은 서로 다르다. 자동 연결·외부 생성 제공자·에디터 원격 편집 지원은 확인된 범위로 기록한다.

## 산출물에서 엔진까지

```text
작업 요구·기존 자료 → 외부 제작/코드 도구 → 산출물 검수
→ 기존 에셋/데이터 계약으로 반영 → 빌드·테스트·실제 장면 확인
→ 변경 근거와 남은 한계 기록
```

게임 고유 규칙·콘텐츠는 game/·프로젝트 에셋, 실행 조합은 apps/, 공유 기반은 engine/에 둔다. 도구가 만든 코드도 [AGENTS.md](../../AGENTS.md)의 소유권·오류 전달·고정 틱·신뢰 경계·가독성 기준을 따른다. 변경 함수의 모든 호출자와 최종 소비자를 확인한다.

## 검수 계약

- 픽셀 에셋은 해상도·PPU·방향·프레임·피벗·투명 경계·팔레트를 확인한다. 소스·이용 조건·수정 이력을 보관한다. 상세는 [픽셀 에셋](05-pixel-assets-ai.md)과 [에셋 파이프라인](../04-asset-pipeline.md)을 따른다.
- 오디오는 형식·길이·루프·레벨·이용 조건을 확인한다. 오프라인 수치 검증과 실제 장치 청취를 구분한다. 재생 수명은 [런타임 계약](../06-runtime-systems.md)을 따른다.
- 대화·번역·게임 데이터는 참조 키·범위·스키마·중복·게임 규칙을 검사한다. 제작 성공이 게임 내 로드·표시 성공을 뜻하지 않는다.
- 코드 변경은 기존 모듈·도우미·표준 라이브러리를 먼저 사용한다. 불필요한 계층·팩토리·캐시·풀을 추가하지 않는다. 성능 주장은 동일 Release 조건의 측정으로 남긴다.

## 자동화의 추가 조건

반복 제작량·수동 오류·실측 비용이 기존 도구의 한계를 보여줄 때 배치·재시도·검수·생성 이력 자동화를 검토한다. 제공자별 모델 ID·가격·요청 필드는 연동 시 공식 문서와 실제 응답으로 확인하며 엔진 지원 목록으로 고정하지 않는다.

인게임 생성이나 다중 사용자 생성 서비스가 실제 요구가 되면 키 보관·인증·입력 검증·예산·timeout·취소·감사·산출물 검수 계약을 먼저 정의한다. 현재 게임 클라이언트에 외부 제공자 키를 넣거나 운영 데이터로 생성 실험하지 않는다.

기존 제공자별 미래 API·가격·모델 표와 미구현 엔진 생성 계층의 필수 도입안은 제거했다. 현재 빌드·캡처·픽셀 도구로 수행할 수 있는 작업에 새 엔진 모듈·게이트웨이를 요구할 근거가 없기 때문이다. 필요성이 확인되면 이 문서의 조건과 [개발 우선순위](../14-development-priorities.md)에 따라 범위를 결정한다.
